# Честный симулятор (контур simulator)

## Что было нечестно (v0.3–v0.7)

| Механизм | Проблема |
|----------|----------|
| Ridge(dt) + суммирование | Σdt не коррелирует с длительностью кейса |
| case-head калибровка | Подгонка под цель, не эмерджентность |
| Синхронный batch-step | Все кейсы «телепортируются» одновременно, нет занятости |
| weekly_corr как KPI | Не доказывает устойчивость к ×2 нагрузке |

Эти режимы остаются в `simulate_batch(queue_mode=false)` для **воспроизведения старых отчётов**.

## Честная «аэродинамическая труба» (v0.10+)

Реализация: `src/orgtwin/sim/queue_des.py`

1. **Слот занятости** — `agent_capacity` (по умолчанию 1).
2. **Очередь FIFO** — заявка ждёт, пока агент занят.
3. **Время обслуживания** — `policy.latency_sec[(agent, action)]` (медиана из fit), не Ridge.
4. **×2 поток** — `input_flow_multiplier`: дублирование кейсов на тех же моментах прихода.
5. **Метрики** — `max_queue_length`, `sum_final_queue_length`, `queue_stats` по агентам.

Включение в JSON:

```json
"sim": {
  "queue_mode": true,
  "agent_capacity": 1,
  "input_flow_multiplier": 2.0
}
```

Быстрый прогон:

```bash
.venv/bin/python scripts/run_queue_stress.py
```

Отчёт: `reports/simulator/queue_stress_bpic2012.json`.
